## 二、当前架构事实

### 1. 主入口

- main.py 是完整自动模式入口，当前展示版本为 v0.2.19。
- 主流程总计 11 步：启动浏览器、预检查 Tidal 首页、创建邮箱、注册 Tidal、进入订阅、查看套餐、选择套餐、填写支付、邮箱验证、保存账号、取消订阅。
- 从 v0.2.13 起，每次程序运行都会创建 data/logs/screenshots/时间戳目录，并在子步骤完成后立即保存全屏截图和 manifest.jsonl。
- 从 v0.2.19 起，每次程序运行会同时创建 data/logs/runtime/run_日期时间.log，记录完整控制台输出。
- 从 v0.2.19 起，在步骤4拿到邮箱和密码后会立即创建 data/accounts_日期时间.txt 账号快照文件。

### 2. 风车邮箱部分

- modules/temp_email.py 继续负责 mail.xoxome.online 登录、创建邮箱、收取验证邮件。
- 风车邮箱流程不纳入 Tidal 专用坐标脚本。
- 如果未来要做邮箱站点的固定坐标或模板化，需要单独建自己的配置，不和 Tidal 混在一起。
- 当前风车邮箱生成链路已经细化为：打开站点、检查登录状态、填写用户名、填写密码、点击登录、选择后缀、点击生成邮箱、等待 10 秒、点击复制、从剪贴板或结果输入框读取邮箱地址。

### 3. Tidal 专用坐标与模板部分

- utils/tidal_coordinates.py 是当前唯一的 Tidal 坐标配置中心。
- 该文件统一维护以下内容：
  - 固定坐标
  - 模板文件名
  - 模板阈值
  - 滚轮次数
  - 等待时长
  - 生日下拉框使用的按键范围
- modules/tidal_register.py 现在已经优先读取这份配置，执行 Tidal 首页弹窗、注册、订阅登录、套餐选择、支付、取消订阅。
- access_restricted.png 也已纳入这份模板配置，用于首页预检查阶段的访问受限判断。
- 访问受限判断当前不再只依赖单次高阈值模板匹配，还会结合多尺度匹配结果和页面文案多来源检测，避免页面已显示“访问暂时受限”却被误判成正常。

### 4. 人类行为模拟部分

- utils/human_behavior.py 当前提供桌面级能力：
  - human_click_coordinate
  - human_type_text
  - human_press_key
  - human_scroll_wheel
- 这些方法会保留随机停顿、鼠标轨迹、输入节奏等人类行为特征。

### 5. 兼容性和兜底

- PyAutoGUI、cv2、numpy、mss 的导入当前都是静默探测。
- 如果 Python 3.12 环境里仍存在 ABI 冲突，程序不会在导入阶段直接崩溃。
- 当桌面坐标点击或模板匹配不可用时，modules/tidal_register.py 对大多数 Tidal 步骤仍保留 Selenium 元素兜底，先保证程序能运行。
- modules/adspower.py 当前优先使用稳定本地驱动链路启动 Chrome，不再默认依赖 Selenium Manager 的在线探测。
- chromedriver 会优先命中精确缓存；若补丁版本不同但 build 相同，也会直接复用本地缓存驱动。
- 当前浏览器启动配置已显式允许 JavaScript，并把反检测脚本收回为只隐藏 navigator.webdriver 的最小版本，避免干扰 Tidal 自己的挑战页脚本。

## 五、当前关键执行逻辑

### 1. Tidal 首页

- Chrome 启动后先固定等待 5 秒，先用 driver.get 打开 https://link.tidal.com/RGZST，再固定等待 20 秒做预检查。
- 访问受限检测通过后，再新开一个 tidal.com 标签页作为主流程页面，并在该标签继续后续注册步骤。
- 先对 access_restricted.png 做多尺度匹配；若高阈值命中、页面文案命中，或低阈值命中分数达到 0.45，则按访问受限页面处理。
- 若命中访问受限页面，则暂停程序并等待用户手动处理，直到用户输入 y 继续复查。
- 先匹配翻译弹窗模板，再匹配 Cookie 弹窗模板。
- 首页弹窗处理完成后，再点击 Create a free account。

### 2. 风车邮箱

- 只有在 Tidal 首页确认可访问后，才会新开邮箱标签页去生成邮箱，避免先消耗风车积分。
- 生成邮箱按钮当前优先用 XPath 文本“生成邮箱”定位，失败时再走 class 和全文按钮文本兜底。
- 生成完成后固定等待 10 秒，再点击“复制”按钮，并优先从 Windows 剪贴板读取邮箱。
- 若剪贴板读取失败，再回退到生成结果输入框和页面文本提取。
- 风车邮箱的打开站点、登录、选择后缀、点击生成、等待 10 秒、点击复制、获取邮箱、等待验证邮件、打开验证链接等子步骤，现在都会各自落一张全屏截图。

### 3. 注册页

- 邮箱注册入口暂时仍保留 DOM 兜底。
- 邮箱输入框、Continue、密码输入框都已经改为固定坐标优先。
- 出生日期已经改为模板点下拉框，再用键盘完成随机选择。
- 条款复选框和 Sign up 已经改为固定坐标优先。

### 4. 订阅登录页

- 邮箱输入、Continue、密码输入、Log In 都已经改为固定坐标优先。
- 如果固定坐标不可用，仍会退回原来的元素流程。

### 5. 套餐选择页

- View Plans 和 Continue 已经改为固定坐标优先。
- 当前仍默认使用 Individual 套餐。

### 6. 支付页

- Full Name、Card Number、Exp. Date、CVC、ZIP 都已经改为模板优先。
- PAY-06 会先滚轮 4 次，再匹配 unchecked.png。
- 如果 PAY-06 模板点击成功，代码不会再执行 DOM 复选框兜底，避免把状态点反。
- PAY-07 已改为模板优先，点击后固定等待 10 秒。

### 7. 邮箱验证与保存

- 邮箱验证仍在风车邮箱页面通过现有 DOM 流程执行。
- 账号保存仍写入 data/accounts.txt。

### 8. 取消订阅

- cancel_subscription 会重新打开 https://account.tidal.com/profile。
- CAN-01、CAN-02、CAN-03 已改为滚轮加模板优先。
- 如果模板路径暂时不可用，仍保留旧的元素查找兜底。
